- 記事は毎月ではなく、国政選挙があった、1か月の変化か地方選挙の外れが誤差を超えた、前回の記事から6か月たった、のどれかの月にだけ出す。今回の理由は「{{REASONS}}」。冒頭の段落で、なぜ今回記事を出したかを一言書く。前回の記事から間が空いていても、事実データの1・12・24か月の変化と、その月の選挙の判定で書く(間の月の話を自分で計算して持ち出さない)
- 大前提: 誤差の範囲の動きを党勢の変化として書かない。世論調査の1回ごとの上下に一喜一憂するのと同じ誤りになる。事実データで「誤差を超える」と付いた変化だけを「上がった」「下がった」と書き、それ以外は「誤差の範囲で、動いたとは言えません」と書く。1か月の変化はほぼ必ず誤差の範囲なので、冒頭や見出しの話題にしない。推定値の動きの大きさを、党勢が動いた理由として説明しない。これは表1に限らず、記事のすべての主張(党どうしの差、支持率との食い違い、相関、選挙の外れ)に当てはまる。事実データに判定(誤差を超える/有意)が付いていないものは「〜と言える」と書かず、判定のない比較を自分で持ち出さない。図や表は、誤差を超える結果があるときだけ載せる
- 指数は党勢指数v3を使う。事実データのv1の節(C_p、前月差の分解、重みシェア、前哨戦の検証、方向の目安)は使わない
- 構成と文体は notes/trend_v2_draft.md と前回の下書きに合わせる(です・ます調)。仕組みの説明は繰り返さず、v2を紹介した記事へのリンクで済ませる。v2からの変更(補選を観測に加えた)は、第2回で一度だけ短く説明する
- 節(2と4は毎月必ず入れる。1は国政選挙があった月だけ、3と5は事実データの判定で有意なものがあるときだけ入れる。指数とつながらない選挙の話は書かない):
  1. 国政選挙(衆参の通常選挙・補選・再選挙)の結果: その月に国政選挙があったときだけ。結果と、選挙前の党勢指数の見込みとの比較を書き、見込みとの差は事実データの判定(見込みから誤差を超えて外れたか)に従って書く。首長選や、指数への影響が誤差の範囲の地方選挙は取り上げない
  2. 党勢指数v3の更新: 各党の値・推定の幅と、事実データの1・12・24か月前からの変化を「+1.2(±3.4)」の形で並べた表(値の大きい順)。変化の列は、1・12・24か月のうち少なくとも1つの党で誤差を超えた期間だけを載せる(どの期間も誤差の範囲なら変化の列は載せず、本文で「どの党の変化も誤差の範囲」と書く)。載せなかった期間は、本文で誤差の範囲だったと一言書く。誤差を超える変化には印(†)をセルの末尾に付け(note用の変換でそのセルに色が付く)、キャプションで±が2標準偏差であること、「†と色付きのセルは誤差を超える変化」であること、変化はさかのぼった月の値も今月までの選挙で推定し直した差なので図1の線の差とは一致しないことを書く。本文では、誤差を超える変化があればそれを、なければ「どの党の変化も誤差の範囲」と書く。推定の幅(水準の幅)が重なるかどうかで変化や順位を論じない。図1は notes/images/dai{{N}}kai_trend_v2.png(コピー済み)を使い、キャプションに1段目の縦軸が対数目盛りであることを書く
  3. 見込みと結果がずれた選挙(事実データに「見込みから誤差を超えて外れたもの」があるときだけ。「なかった」とあれば、この節は見出しごと載せず、党勢指数v3の更新の節で「議会選挙の結果は、どの党も選挙前の見込みの誤差の範囲でした」と比べた件数を添えて一文だけ書く): 事実データに挙がった選挙を表にし、キャプションに、比べた選挙×党の件数と、Holm法で全体の誤りを5%に抑えた判定であることを書く。選挙の結果の話として書き、「党勢を押し上げた」「党の上昇はこの選挙で説明できる」のように党勢の変化の理由としては書かない。勝因などの因果にも踏み込んでよいが、報道や分析の出典を付け、断定せず「〜と考えられます」の形で書く
  4. 政党支持率: 支持率の値の表は載せない(三春さんの集計の転載になり、値はリンク先で見られる)。図2の前に、三春さんの記事へのリンクと更新日を一文で示す。散布図は notes/images/dai{{N}}kai_trend_v2_vs_support.png(コピー済み)を使う。本文で点線から外れていると書くのは、事実データで「誤差を超えて外れている」とされた党だけにする(幅の中の党を外れているとは書かない)
  5. 差の散布図(事実データの差の散布図の「判定」が「記事に差の散布図の節を載せる」のときだけ。「載せない」なら見出しごと省き、ほかの節でも触れない): notes/images/dai{{N}}kai_trend_v2_support_diff.png(出ている中でいちばん長い期間のものをコピー済み)を使い、事実データの「党勢指数v3と政党支持率の…か月差」の相関と順位相関を、点の数と一緒に書く。点が少ないうちは相関の値で結論を出さず、どの党が離れた位置にあるかだけ書く。相関が出ないことを「関係がない」とは書かない(v3の誤差は相関を0に近づけるだけで、検出力が低い)
- 図と表には毎回キャプションを付ける(直後の行に「*図1: …*」「*表1: …*」)
- 選挙の節で事実データにないこと(得票数、対立候補、推薦政党など)は、調べて出典のリンクを本文に付ける
- status に「補間の検証も回し直した」とあれば、notes/trend_model.tex の検証の数字(v3の補間の誤差)を output/trend/ の最新の state_space_glm_validation_*.json に合わせて直す
- note用ファイルは、人が読まずにそのまま公開する(人が読むのは公開後のnote)。確かめきれなかった事柄は、断定せずに書くか、記事から外す。人の確認を当てにして残さない
- 書き終えたら、重複・用語の初出・数値を見直してから `PYTHONPATH=src python3 -m seiryoku.note_export notes/dai{{N}}kai_draft.md` でnote用に変換する。表示される字数が5000字を超えていたら削って変換し直す
- status の警告のうち次のものは、下書きを書く前に自分で対処する。直したら関係するテストを `PYTHONPATH=src python3 -m pytest -q tests/<ファイル>` で回す
  - 略称表にない政党名: どの党かを調べて `src/seiryoku/fetch/miharu.py` の `ABBREVIATIONS` に加え、`data/support_history.json` に略称のまま記録された値を正式名称に直す(tests/test_miharu.py)。分からなければ直さずに報告する
  - 国政補選を取り込んだ: 国政選挙の節を書く前に、当選者と届出党派を報道と突き合わせる。食い違えば `data/national_by_elections.json` を直し、報告の警告に書く
  - 結果の表がない国政補選: 投票日から1か月たっていなければ記事の更新待ちなので何もしない(翌月の実行が取り込む)。1か月以上たっていれば、Wikipediaの記事を読んで `src/seiryoku/fetch/wikipedia_by_elections.py` を新しい書式に合わせる(tests/test_wikipedia_by_elections.py)
  - 国政補選の読み取りに失敗、党勢指数v3を計算できなかった、議会補選の取り込みに失敗: 原因を調べ、コードやデータの修正で直せるなら直してテストを回す。直せなければ原因と必要な対応を報告する
  - パラメータを推定し直した(国政選挙による): 新しい党の結成・合流・分裂がなかったか調べ、あれば `src/seiryoku/lineage.py` の `BRANCH_OF`、`ALLIANCE_MEMBERS`、`ALLIANCE_ORIGIN_SEATS` の見直し案を報告する(コードは直さない)
  - 事実データに効くもの(略称表、補選の記録、v3や補選の取り込みのコード)を直したときは、`PYTHONPATH=src python3 -m seiryoku.cli --force` で月次実行をやり直してから(10〜20分)、新しい事実データと status で書く
