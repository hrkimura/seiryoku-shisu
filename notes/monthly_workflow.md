# 月次更新の流れ(党勢指数v4)

党勢指数v4の定点観測の記事を書くための手順と、Claudeに下書きを頼むときのプロンプトをまとめる。v3はv2の観測に、国政(衆参)と地方議会(都道府県・市区町村)の補欠選挙の議席を加えたもの(2026-10-24から)。国政選挙を1回ずつ外した補間でも、選挙の前日までのデータだけによる予測でも、v2より誤差が小さかった(`output/by_elections/`)。補選の得票率と推薦は、誤差を小さくしなかったので使わない。v4はv3の観測に、英語版Wikipediaの各社の世論調査の政党支持率を加えたもの(2026-11から)。地方選挙の結果が届くまでの遅れを再現した予測で、国政選挙の外れがv3より約3割小さかった(`output/trend/poll/lagged_online_check_oos_2026-11-12.json`)。

## 記事を出す月

データの更新(クロール、月次実行、支持率の取得)は毎月行うが、記事は次のどれかに当たる月にだけ出す(2026-11-11から)。地方選挙だけの月は、党勢の1か月の変化も地方選挙の外れも、ほぼ必ず誤差の範囲に収まるからである。

- 国政選挙(衆参の通常選挙・補選・再選挙)があった
- 1か月の変化が誤差を超えた党がある(8党をまとめてHolm法で判定。v4で2022〜2026年を数えると、国政選挙のない月で当たったのは2025年10月の維新だけ)
- 見込みから誤差を超えて外れた地方選挙がある
- 前回の記事から6か月たった
- 党勢指数をv4に切り替えてから最初の記事がまだない(`monthly_article.V4_FROM`、2026年11月分の第3回で一度だけ)

3か月以上の変化は、国政選挙で一度誤差を超えると長く超えたままになるので、条件に入れない。判定は月次実行が行い(`monthly_article.article_reasons`)、結果は `output/article_decision_YYYY-MM.json` と status の「記事」の節に出る。回の番号は記事を出した月だけに振り、`data/articles.json` に記録する。記事にしない月は下書きを作らず、対処の要る警告があるときだけ、Claudeが `notes/monthly_maintenance_prompt.md` の指示で警告に対処する。

## 自動で行われること

`systemd/` のタイマーで、次のものが自動で走る。更新クロール→月次実行→下書きの生成は、前の段が終わると次が始まる。PCが止まっていた場合は、次に起動したときに実行される。記事は7日以降に公開する想定で、ふつうは4〜5日に下書きができる。

| 日付 | 内容 | 所要時間 |
|---|---|---|
| 毎月2日 | 選挙結果キャッシュの更新クロール(`seiryoku.refresh_cli`)。止まったら毎日11時のウォッチドッグが再開させる。月末の日曜の選挙の結果が載るのを待って2日に始める | 数時間〜十数時間(休止をはさむと2〜3日) |
| クロールの完了後 | 月次実行(`seiryoku.cli`)。国政と議会の補選の取り込み、Wikipediaの世論調査の取り直し、v1とv4の計算、図、記事の事実データ、記事用の図のコピー、警告のまとめと通知 | 15〜25分(推定し直す月は検証と世論調査の部分の推定も回すので、さらに2〜3時間) |
| 月次実行の直後 | 下書きの生成(`seiryoku.monthly_article`、`seiryoku-shisu-draft.service`)。記事を出す月は、`claude -p` が notes/monthly_draft_prompt.md の指示で下書きを書き、そのまま公開できるnote用ファイルに変換する。記事にしない月は、対処の要る警告があるときだけ警告に対処させる | 10〜30分 |
| 毎日12時 | 政党支持率の取得(`seiryoku.support_fetch`)。更新日が新しければ追記する | 数秒 |

三春さんの記事は不定期に更新され、前の値は上書きされて残らない。毎日取りに行くのは、更新を取りこぼさないためである。v4は同じ世論調査を観測に使うので、三春さんの支持率との比較(散布図)は2026年11月から記事に載せていない。取得は、v1の支持率との連動分析のために続けている。通信に失敗した日は、翌日の実行が取り直す。

途中で止まったときの扱いは次のとおり。

- 月次実行は、今月の更新クロールが済むまで走らない。PCを止めていた日があれば、その分だけ下書きも遅れる。
- 取りこぼし用に、月次実行のタイマーが2日以降の6時間おきに起動する。その月の実行が最後まで済むと `output/monthly_run_done_YYYY-MM` ができ、以後の起動はすぐ終わる。実行中に再起動しても、次の起動で最初から取り直される。休止(ハイバネーション)は止まった所から続くだけなので、取り直しにはならない。
- 下書きの生成は、失敗すると30分おきに取り直し、その月に3回失敗したらやめて通知する(回数は `output/draft_failures_YYYY-MM`、`--force` で数え直す)。再起動で止まった場合は、次の月次実行の起動に続いて取り直される。`notes/daiNkai_draft.md` がすでにあれば何もしないので、手で書いた下書きを上書きすることはない。
- 月次実行か下書きの生成が失敗すると、デスクトップに通知が出る。
- ユーザーのタイマーは、ログインしている間だけ動く(lingerは無効)。

月次実行の出力は次のとおり。

- `output/draft_facts_YYYY-MM.txt`: 記事の事実データ。「党勢指数v4」の節(各党の値と推定の幅、3・6・12・24か月前からの変化とその誤差、見込みから誤差を超えて外れた選挙、国政選挙があった月はその見込みと結果の判定)を使う。変化が誤差を超えるかは、期間ごとに全党の変化をまとめてHolm法にかけて判定する(±2標準偏差を少し超えただけでは付かない)。1か月の変化は記事を出すかの判定にだけ使い、表には載せない。選挙の節は国政選挙があった月だけ書き、首長選や指数とつながらない選挙は取り上げない。記事の表1には、どれかの党で誤差を超えた期間の変化だけを載せる。外れた選挙は、その月の全ての選挙×党の予測のp値にHolm法をかけて全体の誤りを5%に抑えて選び、無い月は記事の「見込みと結果がずれた選挙」の節を載せない(地方選挙だけの月はまず出ず、主に国政選挙のあった月に載る)。世論調査は外れの判定に入れない
- `output/status_YYYY-MM.txt`: 警告のまとめ(事実データの警告、略称表にない政党名、推定し直し、確定値/速報値の境界の変化、支持率の毎日の取得の失敗回数、世論調査の取り直しの失敗・読めなかった行・系譜にない政党名)と、記事用にコピーした図
- `output/images/YYYY-MM/trend_v2.png`: 図1(党勢の推移、動きの内訳、首相の在任期間)。動きの内訳には世論調査の帯も入る
- `output/images/YYYY-MM/trend_v2_by_party.png`: 政党別の図(補間の検証の×付き、毎月載せる必要はない)
- `output/trend/state_space_glm_YYYY-MM-DD.json`: v4の計算結果(`model` が "v4"、`polls` に使った世論調査の件数と最新の日付)
- `data/poll_history.json`: Wikipediaの世論調査。読めた行は毎月読み直した値で置き換え、読めなくなった行は残す
- `notes/images/daiNkai_trend_v2.png`: 記事用にコピーした図1。第N回は記事を出した月だけに振る通し番号(`data/articles.json`)

下書きの生成の出力は `notes/daiNkai_draft.md`、`notes/daiNkai_draft_for_note.md` と、Claudeの報告 `output/draft_log_YYYY-MM.txt`(警告、要点、字数、断定を避けた箇所・外した事柄、コミットコマンド)である。

図のファイル名は、記事や手順の参照を変えずに済むよう、v2のときのまま(`trend_v2_*.png`)にしてある。

## 月次実行の後の手順

1. **通知が来たら、`output/draft_log_YYYY-MM.txt` を読む。** 記事にしない月は、通知に「今月は記事にしません」と出る。警告への対処があった月だけ報告ができるので、それを読んでコミットする(以下の2・3は記事を出す月だけ)。 月次実行の警告には、下書きを書くClaudeが先に対処している(`notes/monthly_draft_prompt.md`)。略称表にない政党名は調べて略称表に加え、補選・世論調査やv4の取り込みの失敗は原因を調べて直せるものは直し、データやコードを直したときは月次実行をやり直してから書く。報告には警告ごとにどう対処したかが書かれているので、「直せなかった」とあるものだけ対応する。パラメータを推定し直した月は、新しい党の結成・合流・分裂による系譜の見直し案も報告に入る(採るかどうかは人が決める)。
2. **公開する。** 下書きは読まずに、note用ファイル(`notes/daiNkai_draft_for_note.md`、下書きを書くClaudeが変換済み)をそのまま貼る。画像はアップロードし、キャプション欄に「[キャプション: …]」の中身を入れる。公開後に読んで直したいところがあれば、Claudeに頼む。Claudeは下書き(`notes/daiNkai_draft.md`)を直し、`PYTHONPATH=src python3 -m seiryoku.note_export notes/daiNkai_draft.md` で変換し直す(字数も表示される)。note用ファイルだけを直すと、次に変換したときに消える。
3. **公開版を照合する(任意)。** 公開URLをClaudeに渡して「公開版を照合して」と頼むと、本文と図表を手元のファイルと突き合わせる。
4. **コミットする。** 報告の最後のコマンドを実行する。

下書きが生成されなかったとき(通知が失敗だったとき)は、Claude Codeで `/monthly-draft` と打てば同じ依頼になる。自動で書かれた下書きを捨てて書き直させるときは、`PYTHONPATH=src python3 -m seiryoku.monthly_article --force`。

国政選挙がなくても次の月次実行で推定し直させたいとき(データの読み取りを直したときなど)は、`data/refit_requested` を置く。推定し直しと検証が済むと消える。2026年10月に国政選挙の議席の読み取りを直した分(2019年参院選・2021年衆院選の折り返した党名で抜けていた8議席、2024年衆院選の本人届出の1議席)は、これで11月の月次実行が推定し直す(検証を含めて1時間ほど延びる)。

## 国政の補欠選挙があったとき

衆参の補選(統一補選など)と再選挙は、月次実行がWikipediaの「YYYY年日本の補欠選挙」の記事(前年と今年)から自動で取り込み、`data/national_by_elections.json` に全候補の届出党派・得票・推薦の欄と出典URLを加える。取り込んだ月の月次実行から、v4に入る。推薦は今は使っていないが、比べ直すときのために記録しておく。

取り込んだ補選は、下書きを書くClaudeが当選者と届出党派を報道と突き合わせ、食い違えば直して月次実行をやり直す。投票日を過ぎたのに記事に結果の表がないときは、1か月以内なら記事の更新待ちとして翌月に取り込み、それより長ければ書式が変わったとみて、下書きを書くClaudeが読み取り(`src/seiryoku/fetch/wikipedia_by_elections.py`)を直す。全体のテストにも、記録済みの補選が記事から同じに読めるかを確かめるものがある。

## 国政選挙があったとき

- 総務省の比例代表の得票率が公表されるまでは、月次実行は保存済みのパラメータを使う(画面に表示される)。公表後の月次実行で、自動的に推定し直す。
- 推定し直した月は、国政選挙を1回ずつ除いた補間の検証も月次実行が回し、下書きの生成が trend_model.tex の検証の数字を直す。この検証は世論調査を入れないv3の観測で行う。
- 推定し直した月は、世論調査の部分のパラメータ(`data/trend_glm_poll_params.json`)も推定し直す(8コアで1〜2時間)。v3のどのパラメータに対する推定かを `meta.base_estimated_at` に記録し、食い違えば推定し直す。途中で止まっても、党ごとに書き出した途中の結果から続ける。
- 総選挙のあと、英語版Wikipediaの「Opinion polling for the next Japanese general election」の行は「Opinion polling for the 20xx Japanese general election」へ移る。その月から status に「保存済みの世論調査のうちN件がWikipediaから読めなかった」と出るので、`src/seiryoku/fetch/wikipedia_polls.py` の `PAGES` に新しいページを足す(下書きを書くClaudeが対処する)。足すまでは保存済みの値を使うので、データは欠けない。

- 新しい党の結成、合流、分裂があったら、系譜の対応表(`src/seiryoku/lineage.py` の `BRANCH_OF`、`ALLIANCE_MEMBERS`、`ALLIANCE_ORIGIN_SEATS`)の見直しをClaudeに頼む。合流した名義で戦った国政選挙の議席は、当選者の出身で元の党に分ける。

## 下書きを頼むプロンプト

`notes/monthly_draft_prompt.md` にある。`{{YM}}` と `{{N}}` は、最新の事実データの月と回で置き換えられる。
