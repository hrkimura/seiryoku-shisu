# 月次更新の流れ(党勢指数v3)

毎月の記事を党勢指数v3で書くための手順と、Claudeに下書きを頼むときのプロンプトをまとめる。v3はv2の観測に、国政(衆参)と地方議会(都道府県・市区町村)の補欠選挙の議席を加えたもの(2026-10-24から)。国政選挙を1回ずつ外した補間でも、選挙の前日までのデータだけによる予測でも、v2より誤差が小さかった(`output/by_elections/`)。補選の得票率と推薦は、誤差を小さくしなかったので使わない。

## 自動で行われること

`systemd/` のタイマーで、次のものが自動で走る。更新クロール→月次実行→下書きの生成は、前の段が終わると次が始まる。PCが止まっていた場合は、次に起動したときに実行される。記事は7日以降に公開する想定で、ふつうは4〜5日に下書きができる。

| 日付 | 内容 | 所要時間 |
|---|---|---|
| 毎月2日 | 選挙結果キャッシュの更新クロール(`seiryoku.refresh_cli`)。止まったら毎日11時のウォッチドッグが再開させる。月末の日曜の選挙の結果が載るのを待って2日に始める | 数時間〜十数時間(休止をはさむと2〜3日) |
| クロールの完了後 | 月次実行(`seiryoku.cli`)。国政と議会の補選の取り込み、v1とv3の計算、図、記事の事実データ、記事用の図のコピー、警告のまとめと通知 | 10〜20分(推定し直す月は検証も回すので、さらに40分ほど) |
| 月次実行の直後 | 下書きの生成(`seiryoku.monthly_article`、`seiryoku-shisu-draft.service`)。`claude -p` が notes/monthly_draft_prompt.md の指示で下書きを書き、note用に変換する | 10〜30分 |
| 毎日12時 | 政党支持率の取得(`seiryoku.support_fetch`)。更新日が新しければ追記する | 数秒 |

三春さんの記事は不定期に更新され、前の値は上書きされて残らない。毎日取りに行くのは、更新を取りこぼさないためと、v3の月末の値と比べるときに支持率を月末にそろえる(前後の更新から補間する)ためである。通信に失敗した日は、翌日の実行が取り直す。

途中で止まったときの扱いは次のとおり。

- 月次実行は、今月の更新クロールが済むまで走らない。PCを止めていた日があれば、その分だけ下書きも遅れる。
- 取りこぼし用に、月次実行のタイマーが2日以降の6時間おきに起動する。その月の実行が最後まで済むと `output/monthly_run_done_YYYY-MM` ができ、以後の起動はすぐ終わる。実行中に再起動しても、次の起動で最初から取り直される。休止(ハイバネーション)は止まった所から続くだけなので、取り直しにはならない。
- 下書きの生成は、失敗すると30分おきに3回まで取り直す。再起動で止まった場合は、次の月次実行の起動に続いて取り直される。`notes/daiNkai_draft.md` がすでにあれば何もしないので、手で書いた下書きを上書きすることはない。
- 月次実行か下書きの生成が失敗すると、デスクトップに通知が出る。
- ユーザーのタイマーは、ログインしている間だけ動く(lingerは無効)。

月次実行の出力は次のとおり。

- `output/draft_facts_YYYY-MM.txt`: 記事の事実データ。「党勢指数v3」の節(各党の値・前月差・党勢を大きく動かした選挙)と政党支持率の節を使う
- `output/status_YYYY-MM.txt`: 警告のまとめ(事実データの警告、略称表にない政党名、推定し直し、確定値/速報値の境界の変化、支持率の毎日の取得の失敗回数)と、記事用にコピーした図
- `output/images/YYYY-MM/trend_v2.png`: 図1(党勢の推移、動きの内訳、首相の在任期間)
- `output/images/YYYY-MM/trend_v2_vs_support.png`: 政党支持率との散布図
- `output/images/YYYY-MM/trend_v2_support_diff_{1,3,6}m.png`: v3と政党支持率の1・3・6か月差の散布図(党×期間の点、相関と順位相関を添える)。期間は最新の月末から重ならないように区切る。それぞれ、その期間だけ離れた月末の支持率がそろった実行から出る(1か月差は2026-11、3か月差は2027-01、6か月差は2027-04の実行から)
- `output/images/YYYY-MM/trend_v2_by_party.png`: 政党別の図(補間の検証の×付き、毎月載せる必要はない)
- `output/trend/state_space_glm_YYYY-MM-DD.json`: v3の計算結果
- `notes/images/daiNkai_trend_v2.png`、`daiNkai_trend_v2_vs_support.png`、`daiNkai_trend_v2_support_diff.png`: 記事用にコピーした図(差の散布図は、出ている中でいちばん長い期間のもの)。第N回は2026年8月分を第0回として月から決まる

下書きの生成の出力は `notes/daiNkai_draft.md`、`notes/daiNkai_draft_for_note.md` と、Claudeの報告 `output/draft_log_YYYY-MM.txt`(警告、要点、字数、自信のない箇所、コミットコマンド)である。

図のファイル名は、記事や手順の参照を変えずに済むよう、v2のときのまま(`trend_v2_*.png`)にしてある。

## 毎月の手順

1. **通知が来たら、`output/draft_log_YYYY-MM.txt` を読む。** 月次実行の警告には、下書きを書くClaudeが先に対処している(`notes/monthly_draft_prompt.md`)。略称表にない政党名は調べて略称表に加え、補選やv3の取り込みの失敗は原因を調べて直せるものは直し、データやコードを直したときは月次実行をやり直してから書く。報告には警告ごとにどう対処したかが書かれているので、「直せなかった」とあるものだけ対応する。パラメータを推定し直した月は、新しい党の結成・合流・分裂による系譜の見直し案も報告に入る(採るかどうかは人が決める)。
2. **下書きを確かめて公開する。** 下書きを直したら `PYTHONPATH=src python3 -m seiryoku.note_export notes/daiNkai_draft.md` で変換し直し(字数も表示される)、note用ファイルを貼る。画像はアップロードし、キャプション欄に「[キャプション: …]」の中身を入れる。note用ファイルを直接直した場合は、同じ修正を下書きにも入れる(変換し直すと消えるため)。
3. **公開版を照合する(任意)。** 公開URLをClaudeに渡して「公開版を照合して」と頼むと、本文と図表を手元のファイルと突き合わせる。
4. **コミットする。** 報告の最後のコマンドを実行する。

下書きが生成されなかったとき(通知が失敗だったとき)は、Claude Codeで `/monthly-draft` と打てば同じ依頼になる。自動で書かれた下書きを捨てて書き直させるときは、`PYTHONPATH=src python3 -m seiryoku.monthly_article --force`。

国政選挙がなくても次の月次実行で推定し直させたいとき(データの読み取りを直したときなど)は、`data/refit_requested` を置く。推定し直しと検証が済むと消える。2026年10月に国政選挙の議席の読み取りを直した分(2019年参院選・2021年衆院選の折り返した党名で抜けていた8議席、2024年衆院選の本人届出の1議席)は、これで11月の月次実行が推定し直す(検証を含めて1時間ほど延びる)。

## 国政の補欠選挙があったとき

衆参の補選(統一補選など)と再選挙は、月次実行がWikipediaの「YYYY年日本の補欠選挙」の記事(前年と今年)から自動で取り込み、`data/national_by_elections.json` に全候補の届出党派・得票・推薦の欄と出典URLを加える。取り込んだ月の月次実行から、v3に入る。推薦は今は使っていないが、比べ直すときのために記録しておく。

取り込んだ補選は、下書きを書くClaudeが当選者と届出党派を報道と突き合わせ、食い違えば直して月次実行をやり直す。投票日を過ぎたのに記事に結果の表がないときは、1か月以内なら記事の更新待ちとして翌月に取り込み、それより長ければ書式が変わったとみて、下書きを書くClaudeが読み取り(`src/seiryoku/fetch/wikipedia_by_elections.py`)を直す。全体のテストにも、記録済みの補選が記事から同じに読めるかを確かめるものがある。

## 国政選挙があったとき

- 総務省の比例代表の得票率が公表されるまでは、月次実行は保存済みのパラメータを使う(画面に表示される)。公表後の月次実行で、自動的に推定し直す。
- 推定し直した月は、国政選挙を1回ずつ除いた補間の検証も月次実行が回し、下書きの生成が trend_model.tex の検証の数字を直す。

- 新しい党の結成、合流、分裂があったら、系譜の対応表(`src/seiryoku/lineage.py` の `BRANCH_OF`、`ALLIANCE_MEMBERS`、`ALLIANCE_ORIGIN_SEATS`)の見直しをClaudeに頼む。合流した名義で戦った国政選挙の議席は、当選者の出身で元の党に分ける。

## 下書きを頼むプロンプト

`notes/monthly_draft_prompt.md` にある。`{{YM}}` と `{{N}}` は、最新の事実データの月と回で置き換えられる。
